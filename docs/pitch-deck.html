PART ONE02
The problem

Every AI product forgets, and the fixes are worse than the problem.

TODAY'S FIX 01

Stuff the whole history in

Send every past message with every request. Costs grow linearly, latency with them, and the model still misses the one line that mattered.

TODAY'S FIX 02

Dump it in a vector store

Embed the transcript and hope similarity finds it. Nothing decides what was worth keeping, so noise and signal rank alike.

TODAY'S FIX 03

Overwrite as you go

Keep one row per fact and replace it. The moment a customer asks "why did it think that?", there is no answer left to give.

All three share a failure: they store text, not knowledge. None of them can say what is currently true about a person, how confident it is, or what it believed last month.

THE PROBLEM03
What Memora is

Two calls. Everything else is our problem.

// after the user speaks
await memora.remember({
  userId, content: userMessage
});

// before you answer
const { results } = await memora.recall({
  userId, query: userMessage
});

Send what someone said. Ask for what matters now. Memora decides what was worth keeping, notices when it changes, and hands back the few facts that bear on this moment — each one carrying the reason it was returned.

It extracts, not archives

Durable facts, preferences, goals and decisions — not transcripts.

It versions, never overwrites

A changed fact links to the one it replaced, with the reason it did.

It surfaces contradictions

When two things can't both be true, both come back flagged. It does not pick a side quietly.

It explains every answer

Similarity, confidence, freshness, and a sentence a human can read.

WHAT MEMORA IS04
The wedge

The category leader made a choice that leaves a door open.

In April 2026, mem0 — 63.7k GitHub stars, the default answer for agent memory — rebuilt its algorithm around append-only extraction. When a fact changes, the new one lives beside the old and conflicts are resolved silently at read time. It is faster, and it is a real engineering result.

It also means their architecture cannot tell you why it believes something. There is no stated reason, no flagged conflict, no version with an explanation attached. For a consumer chatbot that is a fine trade. For anyone who has to answer to a regulator, a customer, or an auditor, it is disqualifying.

Memora keeps the judgement and moves it off the response path — same speed, full audit trail. "Memory your compliance team can read" is a sentence they architecturally cannot say.

PART TWO10
How it works · writing

Writes return immediately. Judgement happens behind the response.

01

Extract

One model call turns a message into durable candidate facts — and discards reactions, acknowledgements and small talk.

→
02

Embed

All candidates in a single batched call, so a busy write costs one round trip, not one per fact.

→
03

Store & return

Everything is written and the caller gets their response. Nothing waits on a decision.

→
04

Reconcile

Afterwards, each new memory is judged against what was already known — and the record is repaired.

VerdictWhat happens to the record
ADDGenuinely new. Nothing to repair.
UPDATELinks the new version to the old one and retires the old, with the reason it changed.
MERGEFolds added detail into a single combined fact.
IGNOREA restatement — refreshes the original's confidence instead of duplicating it.
FLAGCannot both be true. Both memories are marked unresolved and surfaced to a human.
HOW IT WORKS · WRITING11
How it works · reading

Two searches, fused — and an answer that shows its working.

Meaning and words, together

Embeddings find what a question is about; a full-text index finds the exact strings embeddings blur — cluster names, ticket ids, channel handles. The two rankings are fused, so a fact found either way still surfaces.

Ranked on more than similarity

Relevance is 60% match, 25% how confident we are the fact is true, 15% how recently it was confirmed. An old, shaky memory loses to a fresh, certain one.

History travels with the fact

Superseded versions do not compete for a slot in the ranking, but they ride along — so "where do they work?" and "did they ever work at X?" are both answerable.

Every field is there so an application — or an auditor — can see why this memory and not another one.

HOW IT WORKS · READING12
How to use it
five minutes

1 · Install and write

npm install @memora/client

import { Memora } from "@memora/client";
const memora = new Memora({ apiKey });

await memora.remember({
  userId: "user_123",
  content: "I'm vegan and allergic to peanuts."
});

2 · Recall before you answer

const { results } = await memora.recall({
  userId, query: userMessage, topK: 5
});

const system = results
  .map(m => `- ${m.content}`)
  .join("\n");

Or skip the code entirely

An MCP server ships with it. Point Claude Code or Cursor at Memora and the agent gets remember, recall, and the ability to record what it learned from a failed task.

Ask why, any time

explain(memoryId) returns the full evidence trail: every source excerpt, every version, and the stated reason for each change.

Narrow it down

Filter recall by memory type, minimum confidence, time window, agent or session — so a support bot and a sales bot never read each other's notes.

Environments, not guesswork

Every key is scoped to one environment. A development key cannot read production memories. Ever.

HOW TO USE IT13
Under the hood

Deliberately boring infrastructure.

STORAGE

One Postgres

Memories, embeddings, full-text index, job queue, rate limits and idempotency all in the same database. No Redis, no vector service, no second thing to page someone about.

INTELLIGENCE

Claude + Voyage

Claude extracts and judges; Voyage embeds. Both are swappable behind an interface — a requirement for enterprises on Bedrock or Azure.

RUNTIME

Stateless app

Next.js in a 290 MB container, non-root, migrations baked in. Scale by adding instances; limits stay correct because they are counted in the database.

DURABILITY

A real queue

Reconciliation jobs are rows, not promises. A crash, a deploy or a failed model call means a retry — never a memory that silently never got judged.

Every architectural choice here was made to reduce the number of things that can be quietly wrong at 3am. The audit trail is the product; losing part of it is not an acceptable failure mode.

THE PLAN16
The ask

Three decisions, and one of them changes everything below it.

DECISION 01

Open source, or not?

mem0's 63.7k stars are a distribution engine we cannot out-run from a closed repo. An Apache-2 core with a hosted tier is the standard answer — and it gives away the engine. This decision shapes every other one.

DECISION 02

Is Experience Memory its own product?

Agents recording what they learned from failed tasks, and being advised by it before the next attempt. It is the one thing mem0 has no equivalent of, and today it is a tab in a dashboard rather than a thing with a name and a price.

DECISION 03

Which vertical goes first?

Support, fintech or health. The answer sets the docs, the examples, the compliance work and the first ten conversations. Picking one beats being generically available to all three.

Everything else on the roadmap is work we can simply do. These three are yours, and until they are answered the sequencing is a guess.
